Machine learning for fire behaviour

Predicting where a wildfire grows next

A ConvLSTM U-Net trained on eight years of California fires, using satellite detections, hourly weather, fuel maps and terrain. This page shows what it predicts, how it was measured, and the experiments that did not work.

What the model does

Given where a fire has burned so far, plus the weather, fuel and terrain around it, the model predicts which currently unburned pixels will burn in the next 24 hours. Everything runs on a 100 metre grid in an equal area projection, cropped to 256 by 256 pixel tiles that follow the active perimeter.

How well it works

The headline metric is the Critical Success Index, the intersection over union of predicted and observed new growth. Reported on fires from 2022 and 2023, which the model never saw.

CSI, pooled0.185all tiles together
CSI, per fire0.099median, the honest figure
False alarm ratio0.78of predicted growth
Detection rate0.56of real growth found

Pooling every tile weights large fires heavily, so a handful of megafires dominate the number. Aggregating per fire weights each fire equally and gives 0.099. Both are reported here because quoting only the pooled figure overstates the result.

Against simple baselines

MethodCSINote
ConvLSTM U-Net0.185this model
Dilate the perimeter by 3 cells0.102strongest naive method
Circular spread at median rate0.079constant radial growth
Persistence0.000see below

Persistence, meaning predict that tomorrow looks like today, is often described as a strong baseline. It scores exactly zero here, and that is structural rather than surprising. The target is new burn, and already burned pixels are excluded from it, so a prediction that copies the current mask cannot intersect the target at all. Beating persistence would have been meaningless, which is why the dilation ring is used instead.

A factor of 3.4 between the smallest and largest quartiles. Small fires have fewer active pixels, a larger share of the perimeter shaped by suppression, and less signal per tile. The 2022 and 2023 seasons were mild and dominated by small fires, so the test split is weighted toward exactly the cases the model handles worst.

Measured the way the field measures

Published benchmarks report average precision, the area under the precision and recall curve, rather than CSI. Average precision has to be read against the positive base rate, because that rate is the score a random guess would earn. The useful quantity is the lift above it.

The comparison also depends entirely on how the target is defined, so both definitions are computed here on the same model and the same test fires.

Target definitionAPBase rateLiftShare of max lift
New growth only, used here0.2420.281%86.3x24.2%
Whole fire mask, used by benchmarks0.9863.706%26.6x98.6%

The top row is in the range of published results, which report 0.274 for a U-Net and 0.280 for a transformer, while predicting a target roughly 13 times sparser. This project excludes cells that have already burned from the target. The benchmarks include them.

The second row is the more useful measurement. Scored the way the benchmarks score, this same model reaches 0.986, which is 98.6 percent of the highest score attainable at that base rate. Predicting the whole fire mask is very nearly solved by copying the input forward, because every cell that is already alight is both given in the input and counted in the answer.

The final column makes the difference concrete. The largest lift any model can achieve is one divided by the base rate. On the strict target this model captures under a quarter of what is available, so there is real headroom. On the benchmark target there is almost none left to win.

This is not a controlled comparison. Different regions, years, fire selection, and a grid ten times coarser than the one used here. It shows these numbers are plausible for the field, not that this model is better. Per fire, the median average precision is 0.174 against the pooled 0.242, the same gap that appears in CSI.

The result that reframed the project

Predictions look like near symmetric haloes around the current perimeter rather than wind driven plumes. To test that impression, each group of input channels was shuffled across the batch, destroying its link to the target while keeping its distribution realistic, and the loss of skill measured.

Input group shuffledCSI lostShare of skill
Current burn mask0.13189%

The burn mask alone accounts for roughly 89 percent of the skill. Wind, the single most important physical driver of fire spread, costs less when destroyed than canopy cover does. Every physical driver combined contributes about a fifth of baseline skill.

This was checked at four different decision thresholds, from 0.30 to 0.95, and the burn mask carries between 81 and 90 percent at every one of them. It is a property of the model rather than an artefact of where the operating point sits.

So beating the dilation ring by 1.8 times is the model learning a better shaped dilation, not learning fire physics. That explains several earlier observations at once: why the recurrent layers bought nothing, why weather side changes did not help, and why skill scales with fire size, since larger fires offer more perimeter geometry to work with.

Other groups find the same thing

This is not specific to one pipeline. The most cited benchmark in the area removes one input at a time and reports that performance barely moves, except when the previous fire mask is removed, at which point it drops sharply. Adding single inputs back alongside the mask, elevation and a vegetation index help most. A later study using attribution methods on the same data ranks the previous fire mask among the top three inputs for both a U-Net and a transformer, and concludes that these models lean on spatial continuity rather than on the weather.

That ordering matches the table above, where vegetation structure and terrain both beat wind. It holds at grid sizes of 1 kilometre, 375 metres and the 100 metres used here, so it is not an artefact of resolution, and swapping in a transformer buys about 2 percent relative improvement for roughly 48 times the computation, which mirrors the recurrence result below.

What we tried

Each of these was run as a controlled change against the same splits, with the success criterion written down before the run rather than chosen afterwards.

Recurrence: does the ConvLSTM earn its cost?

No benefit

Compared against a plain U-Net matched for parameter count. The ConvLSTM won on validation and lost on test. The comparison was then repeated with five timesteps of history and a burn mask that made fire history recoverable only by integrating the sequence, removing both explanations that blamed the inputs rather than the architecture. Across four comparisons the U-Net was equal or better in three. What makes the result trustworthy is not any single number but that the sign flips between splits, which a real architectural advantage would not do.

Regularisation: weight decay, dropout, augmentation

No benefit

Every run overfits from about epoch 8. Weight decay and dropout landed inside seed noise. The augmentation arm posted the best validation score of any run in the project and turned out to be a mirage: it predicted above 0.5 for 98.97 percent of all pixels, against a true positive rate near 0.6 percent.

The cause is an interaction worth knowing about. Label smoothing multiplies with class weighting. Weighted cross entropy puts the optimum for a smoothed target at a probability that scales with the class weight, and at a smoothing of 0.02 with a weight of 103 every negative pixel is pulled to about 0.51. The measured median was 0.515. CSI never revealed it, because CSI at a high threshold is blind to a uniformly shifted probability floor. Only the Brier score and the probability histogram caught it.

Removing the shortcut: incremental burn masks

Made it worse

If the cumulative mask is what lets the model coast on geometry, then giving each timestep only that window's new burn should force the physical channels to carry weight. It did not. The burn mask still carried 87 percent of skill against 88.6 percent before, wind's contribution fell by a factor of five, and validation CSI dropped well outside seed noise. The model did not turn toward physics, it received a worse mask and dilated that instead.

Rebalancing the loss by distance

Mixed

Skill is concentrated near the perimeter, and a single global class weight is part of the reason. The positive rate falls from about 10 percent one cell out to 0.18 percent beyond 3 kilometres, so the balancing weight each distance band needs ranges from 9 to 552. Applying one value of 103 everywhere over weights near positives and under weights far ones, which instructs the model to build a ring.

Rebalancing per band did not improve aggregate far field skill, and the baseline stayed ahead. What it did do is push skill outward: the band beyond 3.2 kilometres improved by a factor of 2 to 2.6, at the cost of the band between 1.2 and 2 kilometres, which holds more pixels and therefore dominates the aggregate.

A shorter forecast horizon

No benefit

At 24 hours each window averages one afternoon run together with one overnight lull, so the wind at any moment is diluted by a full diurnal cycle. Twelve hour windows separate day from night, and the satellite passes twice daily, so each window sits on one side of the cycle. Rebuilding the dataset at 12 hours gives 1.93 times as many samples and 100 additional fires. The mechanism is visible in the data before any model runs: 12 hour windows are 3.7 degrees cooler, with markedly higher variance in both temperature and humidity.

Accuracy did not improve. Compared on the 109 fires both versions share, the median average precision is 0.172 at 12 hours against 0.174 at 24 hours, with the shorter horizon ahead on 47 of those 109. A sign test puts the odds of that pattern arising by chance at roughly one in six, which is no result at all. Comparing the two without pairing them by fire suggests the opposite, because the 12 hour set includes 13 extra fires that are harder than average.

The share of skill held by the burn mask went up, from 85 percent to 94 percent, and wind stayed negligible at every threshold tested. Splitting the windows into daytime and overnight, which only the shorter horizon makes possible, sharpens the point. Daytime windows are 2.7 times more predictable than overnight ones, so the split is real and the model does behave differently across it. Yet even in daytime windows, where fires actually run, wind is beaten by canopy cover by nearly seven times.

Handing the model the wind relationship directly

No benefit

Every attempt above left the weather arriving in the same form. A tile spans roughly 25 kilometres while the weather grid is 3 kilometres, so the wind is close to constant across it, and working out whether a given pixel lies downwind of the fire means combining that near uniform field with the shape of the perimeter, pixel by pixel. That is an awkward thing for this kind of network to compute, so this experiment computes it in advance and supplies it as an extra input: the wind projected onto the direction pointing away from the nearest burning cell.

The channel carries real signal. Before any training, cells that went on to burn sit on average 0.62 metres per second further downwind than cells that did not, in 65 percent of samples.

The model ignores it. Shuffling the new channel changes the score by less than a thousandth, and the direction of that change flips from one training run to the next, which is what noise looks like. Accuracy, false alarms and detection rate all land within the normal variation between runs, and the share of skill coming from the burn mask stays at 89 percent.

This is the most informative of the failures. Each earlier one left room to argue that the model simply could not extract the relationship from the raw wind field. Handing it the exact quantity, per pixel, in physical units, removes that argument. The limit is how weak the signal is, not how it was presented.

Two mistakes worth publishing

Both were caught by measurement rather than review, and both are easy to repeat.

A metric read at the wrong operating point

An early conclusion held that the model was blind beyond 1.2 kilometres, with a detection rate of 0.002. That was an artefact. The threshold had been chosen to maximise pooled CSI, which is dominated by the near perimeter ring, and reading far field skill at that same point understates it badly. The same model at a lower threshold scores 0.086 in the far field rather than 0.051, and 0.145 in the band that supposedly showed nothing. The skill was there and the operating point hid it.

Verifying the convenient property instead of the necessary one

A weather store repair was checked by comparing the list of stored timestamps before and after. Nothing was missing, so it passed. But the list is only an index. The code gates on a separate flag saying the hour holds data, and reads a third array for the values, so an hour can be listed and still be empty, or listed, flagged as present, and hold another hour's weather. Verifying the array that was easy to read rather than the one the code depends on let silent corruption through. The fix was a checker that re-downloads sampled hours and compares them byte for byte.

Honest summary

This is not an operational fire prediction tool and should not be described as one. A median per fire CSI near 0.10, a false alarm ratio of 0.78, and skill that comes overwhelmingly from perimeter geometry together mean the model cannot answer the question that matters operationally, which is which direction a fire will run tonight.

What the project does offer is a complete and reproducible pipeline from raw public data to evaluation, a set of baselines that are honest rather than flattering, and several negative results that are documented in enough detail to save someone else the same experiments. The comparison against FARSITE, the operational benchmark this work set out to beat, has not been run, so that goal is untested rather than achieved.

Built with PyTorch, rasterio, xarray and zarr. Data from NASA FIRMS, NOAA HRRR, LANDFIRE and USGS 3DEP. Predictions shown above come from the wide U-Net checkpoint at its validation selected threshold of 0.95.
